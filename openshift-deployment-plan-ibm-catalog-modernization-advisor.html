Overview

This document describes how to build, push, and operate the IBM Catalog Modernization Advisor static SPA on Red Hat OpenShift. The app is a purely client-side React application with no backend — it is served as a compiled set of static assets by nginx.

Why a Separate Dockerfile

The original Dockerfile runs nginx on port 80 as root. OpenShift's default restricted Security Context Constraint (SCC) forbids root UIDs and privileged ports (<1024). Dockerfile.openshift fixes this:

  • Custom nginx.conf binds to port 8080.
  • All nginx temp/log paths redirected to /tmp (writable by any UID).
  • chmod -R 777 on cache/run/log dirs during build so the random OpenShift UID can write them.
  • Explicitly sets USER 1001; OpenShift will override with its assigned UID, but the non-root flag is satisfied.
The original Dockerfile is left untouched — it still works for local development and other container platforms.

Step-by-Step Deployment

1
Create the namespace
oc new-project ibm-catalog-advisor
2
Update the Git URI in BuildConfig

Open openshift/buildconfig.yaml and replace the placeholder Git URL:

uri: https://github.com/YOUR_ORG/watsonxchallengehorizon2.git

If the repository is private, also create a Secret and reference it via spec.source.sourceSecret.

3
Apply all resources with Kustomize
oc apply -k openshift/

This applies resources in the correct dependency order: ImageStream → BuildConfig → Deployment → Service → Route.

4
Trigger and monitor the first build
# Trigger manually (first run)
oc start-build ibm-catalog-advisor --follow

# Check build logs
oc logs -f bc/ibm-catalog-advisor
5
Watch the rollout
oc rollout status deployment/ibm-catalog-advisor

The Deployment watches the ImageStream; once the build completes it will automatically roll out the new pods.

6
Get the public URL
oc get route ibm-catalog-advisor -o jsonpath='{.spec.host}'

Open https://<that hostname> in your browser. The Route uses TLS edge termination — HTTP is automatically redirected to HTTPS.

Alternative: External Registry (no BuildConfig)

If you prefer to build the image in CI/CD and push to an external registry (Quay, DockerHub, GHCR):

# Build locally with the OpenShift Dockerfile
docker build -f Dockerfile.openshift -t quay.io/YOUR_ORG/ibm-catalog-advisor:latest .
docker push quay.io/YOUR_ORG/ibm-catalog-advisor:latest

# Skip imagestream.yaml and buildconfig.yaml — just apply the runtime resources
oc apply -f openshift/deployment.yaml
oc apply -f openshift/service.yaml
oc apply -f openshift/route.yaml

Update the image: field in deployment.yaml to your registry path, and create an imagePullSecret if the registry requires authentication.

Manifest Design Decisions

ManifestKey decisions
deployment.yaml 2 replicas, RollingUpdate with maxUnavailable: 0 (zero-downtime).
runAsNonRoot: true + allowPrivilegeEscalation: false + all caps dropped (satisfies restricted SCC).
Liveness & readiness probes on GET /healthz.
CPU 50m–200m · Memory 64Mi–128Mi (suitable for a static file server).
service.yaml ClusterIP on port 8080 — only the Route is exposed externally.
route.yaml TLS edge termination. OpenShift manages the certificate. HTTP → HTTPS redirect enforced.
imagestream.yaml lookupPolicy.local: true — pods in the namespace can reference the stream by short name.
buildconfig.yaml Docker strategy using Dockerfile.openshift. GitHub & generic webhook triggers + base-image change trigger.
kustomization.yaml Single-command apply; namespace label injected into all resources. Use the images: patch to pin a specific tag.

Day-2 Operations

Scale replicas

oc scale deployment/ibm-catalog-advisor --replicas=3

Roll back a bad release

oc rollout undo deployment/ibm-catalog-advisor

Set up CI/CD webhook

# Retrieve the webhook URL
oc describe bc/ibm-catalog-advisor | grep -A2 "GitHub"

Paste that URL into your GitHub repository's Settings → Webhooks. Every push to main will trigger a new build and automatic rollout.

Update the image tag in Kustomize

Add to openshift/kustomization.yaml:

images:
  - name: image-registry.openshift-image-registry.svc:5000/ibm-catalog-advisor/ibm-catalog-advisor
    newTag: v1.2.3

Then re-apply with oc apply -k openshift/.

Before going to production, store any secrets (webhook secret, image pull secret) in OpenShift Secret objects rather than embedding them in YAML files. Consider adding a HorizontalPodAutoscaler if traffic is variable.
